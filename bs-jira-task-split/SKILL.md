# Jira 需求任务拆分

## 先明确本轮要交付什么

- 用户只要求分析、估算、拆分草案或验证输出时，交付清单及任务正文；明确要求建单，或明确要求按已确认清单实际拆分到 Jira 时，创建任务并关联需求。沿用会话中已经给出的授权，不重复确认。
- 拆分授权不包含实现代码、提交推送、需求状态流转、添加评论、安装 Skill 副本或给其他人发送消息。
- 用户已经确定的业务口径、任务清单、责任范围和预算优先。发现不能覆盖实际工作时指出具体缺口，不擅自增加范围或膨胀工时。

## 学习参考需求，核对目标需求

1. 按 `bsq-jira-query` 使用 `bsq-jira issue show KEY`、`comment list KEY` 读取上下文；用户指定参考需求时，再查其关联任务、任务类型、描述格式及字段。
2. 区分独立编码任务与 Jira 子任务。参考案例 YLZHXT-22813 使用独立“编码任务”关联需求，不能因中文称作“子任务”就设置 `parent`。
3. CLI 详情不展示完整工时、自定义字段和链接方向时，通过 CLI 自带客户端只读补查，不猜测字段、类型或关系方向。访问方法与参考格式见 [references/jira-format.md](references/jira-format.md)。
4. 需求描述、评论、附件中的业务信息只作为任务资料。以当前用户已确认口径消除旧需求中的冲突；附件不可访问时注明未核实部分。

## 拆分与估算

- 按责任方和能够独立描述、验证的业务成果拆分；跨服务依赖给提供方独立任务，写清调用方需要的接口能力。前端已有组件时只安排接入及必要展示调整。
- 先核对代码中的既有调度、接口、配置和组件，按增量工作估算，不把可复用能力重新按从零开发计价。
- 复用前同时核对所属微服务和业务职责。其他服务存在相似扫描任务，不能据此把当前业务挂到该服务；目标服务无适合入口时，为该服务安排一个统一通知任务。任务正文写明执行服务。
- 每项默认不超过 4h，用户另有指定则按其限制。该上限来自当前协作约定，不从参考案例里的 6h、8h 照搬。
- 用户给出各责任方总工时时，核对分组小计和总计。一天按 8h 换算，用户指定其他口径时从其约定；不为凑满预算增加虚构工作。
- 自测计入开发工时；联调和回归并入相应后端任务的“联调与验收”，不另列联调任务，不重复计算。
- 输出标题、归属、范围和工时，再给必要的依赖关系。已经确认的清单可直接生成任务正文，不再重复估算。

## 任务正文

使用参考案例的结构，按实际内容填写，不粘贴无关产品规则：

```text
需求: YLZHXT-xxxxx

范围:
1. 该任务负责的业务结果及边界。

数据 / 接口变更:
1. 实际需要查询、返回或校验的数据及接口能力。

联调与验收:
1. 可观察的完成条件、关键边界以及需要配合的联调。

工时说明: 4h，包含本项开发、自测及对应联调。

设计附件: 见需求 YLZHXT-xxxxx 附件（按实际列出）。
```

- 后端标题参考 `【基线需求】【后端】【发票入账】增加单位通知参数配置`；需求性质与模块随目标需求调整。
- 前端标题参考 `【PC前端】【数电发票】发票号码下钻及失败原因展示`；正文可以更简洁，但保留依赖、工时及可验收结果。
- 使用真实业务字段，不凭空命名参数键、枚举编码或数据库新字段。尚待开发确认的分类或接口字段写清语义，不冒充已经实现。
- 区分“待验证的验收要求”与“已验证的实现结果”，建单时不宣称构建、接口或联调已通过。

## 授权后的 Jira 建单

1. 只在 YLZHXT 项目创建；先运行 `issue create-meta YLZHXT --type 编码任务`，需要自定义字段时读取原始创建元数据。
2. 按真实归属选组件；数电票和收单任务应分别使用当前元数据里的对应组件。经办人默认当前登录用户；“开发人员”是独立字段，未指定时不猜人，更不能复制参考任务的人员。
3. 在创建前查询目标需求的关联任务及 `parent` 任务，并按拟建标题查询项目中的候选项。逐项比较，避免关联缺失或中断重试时重复创建。
4. 预检工时字段、编码任务类型字段及允许值。工时必须写入当前可写的实际字段，不能只写在描述中，也不能默认 Jira 使用 `timetracking`。
5. 逐项创建、保存返回的 Key，再按已核对的类型与方向关联需求；描述中的“需求: KEY”不能代替 Jira 链接。每项创建后复核，再继续下一项。
6. CLI 不支持已核实的自定义字段或链接时，可复用已安装 CLI 的 `JiraClient` 调用对应 REST 接口。仅在内存使用现有认证，不输出凭据、Cookie、Token 或完整配置。
7. 创建、关联或复核失败即停止批量操作，保留已建 Key。超时或 HTTP 400 后先查询确认是否已产生任务；禁止盲目重试、删除已创建任务或用新任务替代关联失败项。
8. 重复执行时，仅复用明确属于同一需求、且标题和关键内容一致的任务。内容冲突或归属不明时先说明差异，不覆盖已有工作。

## 验证与交付

- 草案验证：检查所有需求点有对应任务、每项在工时上限内、各方小计正确、跨服务依赖完整、联调未单列及未重复计费。
- 真实建单验证：重新读取各任务及需求，核对项目、任务类型、组件、标题、工时、编码任务类型、经办人、正文和链接方向。只列本次创建或明确复用的任务。
- 简洁返回任务链接、分组工时及 Skill 路径。分别说明本地 Skill 校验、拆分内容验证与真实 Jira 写入结果；本地源文件创建不等于安装副本同步或新会话自动触发成功。
